Obiettivo
Migrare l’app “ChironHedge Financial Research Platform” (React 18, TypeScript, Tailwind CSS, Chart.js/Recharts) a Next.js, abilitando SSR/SSG per performance, SEO e Core Web Vitals ottimizzati, senza interrompere il flusso di sviluppo.

Prima di iniziare
	1.	Spiega in 1–2 frasi cosa farai e perché (linguaggio semplice).
	2.	Elenca i passi che affronterai e chiedi subito conferme o integrazioni se vedi punti ambigui.

Fasi di lavoro
	1.	Setup iniziale di Next.js
	•	Crea un nuovo progetto Next.js con TypeScript (npx create-next-app@latest --ts).
	•	Installa e configura Tailwind CSS nella struttura Next (tailwind.config.js, import in globals.css).
	•	Verifica che l’ambiente di sviluppo (npm run dev) funzioni correttamente.
	2.	Struttura delle pagine e routing
	•	Converte ogni route React/Wouter in file nella cartella pages/ (o app/ se usi l’App Router).
	•	Per le pagine dinamiche (es. dettagli ricerche), usa [slug].tsx con getStaticPaths + getStaticProps (SSG) o getServerSideProps (SSR) secondo necessità.
	•	Spiega brevemente la differenza tra SSG e SSR e chiedi quale preferisci per quali contenuti.
	3.	Migrazione dei componenti
	•	Sposta i componenti comuni in components/ e aggiorna import (next/link, next/image).
	•	Sostituisci <Link> di React Router con next/link e <img> con next/image per lazy-loading e ottimizzazione.
	•	Verifica che Chart.js/Recharts funzioni sotto SSR o wrappa con dynamic-import (next/dynamic + { ssr: false }) se necessario.
	4.	Meta-tag e dati strutturati
	•	Usa il componente <Head> di Next per ogni pagina: <title>, <meta name="description">, Open Graph, Twitter Card, canonical.
	•	Inserisci JSON-LD in <Head> o tramite un componente dedicato Seo.tsx che riceve props (title, description, image, url).
	5.	Ottimizzazione delle performance
	•	Verifica il funzionamento del Image Optimization di Next (next/image).
	•	Abilita e configura next.config.js per compressione (brotli), headers di caching e SWR per dati dinamici.
	•	Controlla i Core Web Vitals con next build && next telemetry disable e Lighthouse, e documenta gli eventuali miglioramenti.
	6.	Sitemap, robots.txt e prerendering
	•	Aggiungi uno script o usa un pacchetto (es. next-sitemap) per generare sitemap.xml e robots.txt automaticamente al build.
	•	Controlla che la sitemap includa tutte le pagine SSG/SSR.
	7.	Test end-to-end e verifica SEO
	•	Esegui test manuali: navigazione, caricamento di ogni pagina, link interni, fallback dynamic routes.
	•	Lancia un nuovo audit SEO con Lighthouse e confronta con l’audit precedente da React “plain”.
	•	Invia un breve report con metriche LCP, FID, CLS, score SEO e performance.

Stile di comunicazione
	•	Prima di ogni blocco, spiega brevemente “cosa” e “perché” in un paio di frasi.
	•	Se qualcosa non è chiaro (es. strategie di prerender, scelte SSR vs SSG), chiedi subito chiarimenti.
	•	Fornisci note concise sulle tecnologie usate (es. “Ho scelto SSG per le pagine di ricerca perché…”).

Consegna finale
	1.	Un branch o commit con il progetto migrato a Next.js, pronto per il build di produzione.
	2.	File di configurazione (next.config.js, tailwind.config.js), sitemap.xml, robots.txt, componenti SEO.
	3.	Report comparativo (React plain vs Next.js) con metriche SEO e Core Web Vitals.
